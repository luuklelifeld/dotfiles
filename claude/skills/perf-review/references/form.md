# Personio Annual Review Form — Structure and Field Guidance

The final deliverable is paste-ready text for each field below, in this order. `<TEXT>` marks a free-text field; `[ ]` marks a single-choice rating.

## Section 1: AoR Performance Assessment

Every AoR goes into exactly one of the four fields below. Not all fields need to be used — write "Not applicable" in unused ones. For each AoR listed: name the AoR clearly, give supporting evidence/examples, and reference every KPI tied to it.

### 1a. AoRs performed above expectations `<TEXT>`
Evidence must show performance beyond the expected standard, referencing each KPI.

### 1b. AoRs consistently performed at the expected level `<TEXT>`
This usually holds the core of the role. Name each AoR, give context or examples, reference every KPI.

### 1c. AoRs requiring improvement `<TEXT>`
For each: name the AoR, describe the gap, explain its impact. With multiple KPIs, state which are met and which are not.

### 1d. AoRs not met due to unsatisfactory performance `<TEXT>` (optional)
Only if applicable. Outline the AoRs not met, the severity of the gap, and the business or team impact.

## Section 2: Ways of Working

Six ratings, each one of: **Exceeds Expectations / Meets Expectations / Needs Improvement / Unsatisfactory**

1. **Planning and Delivery** — time management, planning, prioritisation
2. **Communication** — clear and constructive; follows escalation procedure
3. **Quality of Work** — care regarding procedures, processes, security regulations
4. **System Administration** — keeping relevant systems up to date per procedure
5. **Velocity** — speed of work, on-time delivery
6. **AI Adoption & Application** — per the Publitas AI Capability Framework, based on real observed examples, not stated intent or one-off experimentation:
   - *Exceeds*: builds reusable workflows, tools, prompts, or playbooks that improve how the team works
   - *Meets*: AI is a standard part of their work (drafting, summarising, comparing options) with good validation judgment
   - *Needs Improvement*: occasional basic use, inconsistent, doesn't validate outputs or look for wider use cases
   - *Unsatisfactory*: rarely or never uses AI even where it would clearly help

### 2b. Additional context on how work was delivered `<TEXT>`
Patterns, strengths, or improvement areas across: quality, communication, organisation and reliability, system usage and ownership, speed and delivery. Include examples.

## Section 3: Development Priorities `<TEXT>`

The 2–3 highest-impact priorities for the next period — not a laundry list. For each:
- What needs to improve
- Why it matters
- Specific actions or support that would help

## Section 4: Strengths `<TEXT>`

Strongest contributions. For each strength:
- The behaviour or capability
- Its impact on team or business
- Examples or outcomes

May reference StrengthsFinder insights if the user has them. Strengths must be specific, observable, and impactful — not generic traits.

## Section 5: Overall Performance Rating

### 5a. Justification `<TEXT>`
- Summarise the overall performance level
- Highlight the most important strengths and gaps
- Explain how performance compares to expectations for this role, given scope and complexity
- Reference impact, consistency, and scope

### 5b. Final thoughts `<TEXT>` (optional)
Any context that helps ensure a fair and complete assessment.

### 5c. Overall Performance Evaluation
One of: **Unsatisfactory / Needs Improvement / Meets Expectations / Exceeds Expectations**

This is an overall judgment, not an average of the sections above.

## Delivery format

Output each field as:

```
=== [Field name] ===
[paste-ready text, or the chosen rating on its own line]
```

Finish with the AoR checklist:

```
=== AoR checklist ===
- [AoR name] → [bucket]
- ...
```
